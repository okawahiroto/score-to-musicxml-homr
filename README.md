# 楽譜 → MusicXML

PDF や写真の楽譜を MusicXML に変換するローカル Web アプリです。ブラウザにファイルを
ドロップすると認識結果が楽譜として画面に描画され、MusicXML をダウンロードできます。
楽譜ファイルの変換はすべてこのMacの中で行い、ファイルを外部に送ることはありません。
ただし画面上の楽譜プレビューは、OpenSheetMusicDisplayをjsDelivr（CDN）から読み込んで
描画します。表示にはインターネット接続が必要で、jsDelivrにはアクセス元のIPアドレスなどが
伝わります（スクリプトはSRIで改ざん検知しています）。

認識エンジンは [homr](https://github.com/liebharc/homr) を使っています。

## セットアップ

```bash
brew install uv
uv sync
uv run homr --init
```

`uv sync` が Python 3.12 の仮想環境を作り、依存関係を入れます。`homr --init` は
認識モデル（約 124 MB）を取得します。初回だけ必要です。

## 起動

### 通常の使い方: ScoreToXML.app

> `ScoreToXML.app`はリポジトリに含まれません。作者がAppleScriptで作った個人用のランチャーです。
> 同じ操作は`./scripts/open-app.sh`で再現できます。

Launchpad、Dock、または`/Applications`から**ScoreToXML**を起動するだけです。
コマンドもClaudeも不要です。

クリックすると、内部で次の処理が順番に走ります。

1. `http://127.0.0.1:8765/api/health`に問い合わせ、本アプリのサーバーが動いているか確認する。
   応答が本アプリのものかを見るので、別のアプリが同じ番号を使っていても取り違えない
2. 動いていなければ、`.venv/bin/python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8765`
   をバックグラウンドで起動し、ログを`data/logs/`に書き出す。起動完了まで待つ。
   8765番を別のアプリが使っている場合は、エラーを表示して終了する
3. 既定のブラウザで`http://127.0.0.1:8765/`を開く

`ScoreToXML.app`はAppleScriptを`osacompile`でコンパイルした薄いランチャーで、
実体は`scripts/open-app.sh`を呼んでいるだけです。すでにサーバーが起動していれば
手順1で終わり、ブラウザを開くだけです。

### 手動起動（開発時など）

```bash
uv run uvicorn app.main:app --host 127.0.0.1 --port 8765
```

## 使い方

1. PDF / JPG / PNG をドロップする（上限 50 MB）
2. 進捗が終わるのを待つ
3. 「楽譜プレビュー」で認識結果を確認する
4. 「認識結果の重ね絵」で、元画像のどこを五線として拾ったかを確認する
5. MusicXML をダウンロードし、MuseScore などで校正する

複数ページの PDF は各ページを解析したうえで 1 本の MusicXML に結合します。

## 処理時間の目安

Apple Silicon の Mac で、ピアノ譜 1 ページあたり **約 10 秒**です。
セグメンテーションは CoreML 経由で GPU / Neural Engine を使います。追加設定は不要です。

3 ページ以上のときだけ `--coreml-encoder` を自動で付けます。このオプションは起動時に
26〜60 秒のモデルコンパイルを伴うため、少ページでは逆に遅くなります。

## 精度について

OMR は完璧ではありません。**下書きを作る道具**として使い、MuseScore での校正を前提に
してください。

- 手書き譜には対応していません
- 強弱記号・アーティキュレーション・重複調号（ダブルシャープ等）は認識対象外です
- 撮影した写真は、傾き・影・ピンボケが少ないほど精度が上がります

## 構成

```
app/
  main.py        FastAPI のルート定義
  jobs.py        ジョブ状態の管理とワーカースレッド
  converter.py   homr の呼び出しと出力ファイルの回収
  static/
    index.html   UI 一式（OpenSheetMusicDisplay で楽譜を描画）
data/jobs/       ジョブごとの作業ディレクトリ（変換結果もここに残ります）
scripts/         サーバー確認・起動・ブラウザ表示のスクリプト
assets/          アプリのアイコン
```

動作確認用の楽譜は同梱していません。ご自身に権利のある楽譜をお使いください。

### homr の呼び出しについて

homr の CLI には出力先を指定するオプションがなく、書き出し先が 2 系統に分かれます。

- 単ページの結果は入力ファイルと同じ階層
- 複数ページ結合の結果はカレントディレクトリ

そのため `app/converter.py` はジョブごとの作業ディレクトリに入力を置き、そこを
カレントディレクトリとして homr を起動します。出力名はページ数で変わるため、
決め打ちせずディレクトリを走査して回収しています。

### 依存を git コミットに固定している理由

PyPI の homr 0.7.0 には PDF 入力と複数ページ結合が入っていません。どちらも
main ブランチの未リリース分のため、`pyproject.toml` でコミットを固定して取得しています。

## セキュリティ上の前提

このアプリは認証機能を持たない、ローカル専用の道具です。

- `127.0.0.1`以外に公開しないでください（`--host 0.0.0.0`での起動は避けてください）
- `Host`が`127.0.0.1`か`localhost`以外のリクエストと、別サイトのページからの書き込み
  （POST・DELETE）は拒否します。悪意あるWebページからの操作やDNS rebindingを防ぐためです
- クリックジャッキング対策のヘッダーを付け、`/docs`などの自動生成ドキュメントは無効にしています
- 変換結果は`data/jobs/`に残ります。不要になったら画面から削除するか、フォルダごと削除してください

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| 「五線や音符を検出できませんでした」 | 楽譜が画面いっぱいに写っているか、解像度が足りているかを確認する |
| 「五線を検出できませんでした」 | 傾きや影を減らして撮り直す。真上から撮ると安定する |
| 一部のページだけ変換された | 失敗したページを画像として単独で投入してみる |
| 音価がずれる | homr の既知の弱点。MuseScore 側で直す |
